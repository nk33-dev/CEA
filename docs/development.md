# 开发说明

## 启动和验证

需要 Node.js 24 或更高版本。

```bash
npm ci
npm run dev
```

开发页面是 `http://127.0.0.1:5178`，接口服务默认使用 `5179`。日常浏览建议使用 `npm run build` 和 `npm start` 运行构建版。

修改后运行：

```bash
npm run typecheck
npm test
npm run build
```

浏览器测试使用 Playwright，默认访问 `http://127.0.0.1:5180`。首次运行先安装 Chromium：

```bash
npx playwright install chromium
```

启动构建版服务后，在另一个终端运行 `npm run test:browser`。部分测试使用合成数据，部分需要专门准备的组件；后者不能在空库直接运行。会写入数据的测试应使用独立测试库，勿连接个人收藏库。可通过 `CEA_TEST_URL` 指定测试服务地址。

## 项目结构

| 目录 | 负责什么 |
| --- | --- |
| `src/pages/` | 浏览、详情、编辑、整理、导入导出与设置页面 |
| `src/components/` | 预览、代码查看、筛选和表单控件 |
| `src/lib/` | 接口请求、偏好、预览会话和代码着色 |
| `shared/` | 前后端共用的类型、提示词、语言及导入格式 |
| `server/` | HTTP 服务、预览打包、素材库和命令行 |
| `server/db/` | 数据库结构、迁移及 SQL |
| `server/transfer/` | ZIP、组件文件夹的导入导出及词条匹配 |
| `tests/` | 单元测试、合成数据及浏览器交互测试 |

收藏的组件、提示词、媒体、数据库和备份放在外部素材库，不作为内置示例加入程序仓库。单元测试使用临时目录与小型合成数据。

## 内容和预览约定

三种复用内容由 `shared/prompt.ts` 生成，复制和导出使用完整的原始内容，代码着色和按可见区域渲染不能改变它们。

HTML 实现使用 `markup.html`、`style.css` 和 `script.js`。React、Vue 的入口组件可以引用同目录文件与样式，服务端用 Rolldown 本地打包。每个框架只保存一份原始实现，主题差异在组件内部处理，不复制整套源码。

组件 ID 由小写字母、数字和连字符组成，也是素材目录名。统一播放地址是 `/play/<id>/<框架>/`，省略框架时使用第一个实现；编辑草稿走 `/play/~draft/<token>`。

预览放在无同源权限的 sandbox iframe 中。修改类接口要求 `x-cea-client: 1` 请求头，用来隔离预览代码与素材库写入；它不是面向公网服务的完整身份认证。服务默认仅监听 `127.0.0.1`。

组件主题、舞台背景、AI 配色目标和网站偏好各自独立。修改相关行为前先阅读[配色与预览](themes.md)。旧组件缺少声明时按原样读取，不根据组件 ID 自动改写源码或文案。

## 加载与交互

页面按路由加载，详情数据与页面模块并行请求。代码区先显示可读原文，再由 Worker 着色，长代码通过 TanStack Virtual 按可见区域渲染。

列表中的预览按视口位置加载和释放，离屏组件不应一直运行。切换语言、舞台背景等展示状态不应重新挂载预览。详情和编辑共用设备预览与缩放逻辑，切换编辑页签时保留草稿和 iframe，并暂停隐藏预览。

播放页等待字体及首帧就绪后报告状态。更新代码或重播时保留旧画面，直到新预览可以交接。验证加载体验应覆盖首次显示、切换设备、放大拖动及原生弹层，不只检查最终静止截图。

缩放与平移由 `react-zoom-pan-pinch` 管理，iframe 消息和滚动适配见[预览导航](preview-navigation.md)。

## 扩展入口

添加框架时，在 `shared/frameworks.ts` 注册入口和模板，再在 `server/bundler.ts` 补充挂载及文件编译处理。

添加内容语言时，在 `shared/i18n/` 提供完整语言包，并在 `shared/locales.ts` 注册。选择器、回退、说明和提示词复用统一入口，不在页面逐处增加语言判断。维护步骤见[内容语言](i18n.md)。

类型中还预留了 `brand`、`guide` 和 `page`。这些字段不代表对应浏览视图已经完成；增加界面支持时，需要一起检查筛选、预览和复用面板。
