# 配色与预览

## 状态边界

| 用途 | 入口 | 作用 |
| --- | --- | --- |
| 组件主题 | `AppearanceToggle`、`previewThemeFor` | 只切换明确声明为双主题的实现，初始使用实现声明的默认配色 |
| 舞台背景 | 详情和编辑预览工具栏中的太阳 / 月亮选项，`DeviceBackground` | 只改变组件外的舞台，初始为浅色，不改变源码和 AI 目标 |
| AI 配色目标 | `themeChoices`、`themePrompt` | 沿用原配色、浅色、深色、双主题；只影响生成的提示词 |
| 网站主题 | 顶栏、`PREF_UI_THEME`（`cea:ui:theme`） | CEA 浅色、深色、跟随系统的独立偏好，不控制组件预览 |

详情和编辑页通过 `usePreviewSession` 保存临时预览状态，退出页面即丢弃；AI 目标同样只在当前详情有效。首页始终使用中性浅色舞台和组件原始默认配色。
旧的 `cea:component-theme`、`cea:theme` 本机值不再读取，也不作为网站偏好的回退。
播放页的舞台底色使用 `--cea-background`，不覆盖组件可能使用的 `--stage-bg` 配色变量。

网站主题通过 `html[data-ui-theme]` 和界面 tokens 生效（包括 `--code-editor-bg`、`--code-editor-fg`）；启动时在首屏绘制前恢复偏好。预览舞台使用独立的 `--preview-light` / `--preview-dark`，不要用网站主题重写组件配色或重载 iframe。

全局换色由 `uiThemeMotion` 和构建阶段的 `build/themeMotion.ts` 配合完成，使用浏览器原生 CSS 颜色过渡，统一为 180ms。PostCSS 只为声明主题颜色变量的规则补充过渡：没有局部过渡时放在低优先级层，有局部过渡时追加颜色时序，保留原有位移、旋转和显隐行为。新增配色沿用现有 tokens，规则自动覆盖 Logo、正文、分隔线、导航、代码高亮和门户弹层。

运行时只切换根节点状态，完成后恢复控件原有悬停时长；不扫描 DOM、不注册插值变量、不捕获整页快照，也不暂停、重载预览。快速反向切换由 CSS 从当前颜色续接。顶栏和筛选栏使用实色表面；`html` 明确绘制网站底色，`body` 至少覆盖视口。换色验收包含页面留白、顶栏、卡片和阅读区，不能只检查顶栏。

思路正文使用 `--fg-2` / `--well`，源码阅读和编辑使用 `--code-editor-fg` / `--code-editor-bg`。语法高亮通过 `--syntax-*` 定义两套可读配色；选中标记的图形使用对应填充的反色，表单悬停、占位文字和状态提示同样使用主题 tokens。组件源码、预览舞台和品牌色不参与网站配色迁移。

预览容器明确声明自己的 `color-scheme`，阻断网站配色向内嵌媒体传播；设备屏幕背景使用 `--preview-light` / `--preview-dark`，不能使用网站的 `--well`。组件主题仍由素材契约和预览会话控制。首屏恢复、减少动态效果和后台页面直接切换配色。SVG 使用 `currentColor`，品牌点保持原色。验收检查实际播放中的图形、文字、分隔线和预览像素，不以计算颜色或手动跳到中间帧代替实际播放。

## 预览视图

详情和编辑共用 `DeviceWorkspace`。默认「组件」视图按播放页报告的内容边界居中、适配，最多显示到原始大小；不改变组件的 CSS 尺寸。「电脑」「手机」按配置的真实视口排版，再将整个设备缩放进画布。切换视图保留 iframe，尺寸、旋转和缩放只属于当前预览会话。

「组件」和列表缩略图使用居中舞台。「电脑」「手机」使用设备布局，不注入舞台 padding 或强制居中，保留素材自己的间距与排版。布局通过 `framing` 初始参数和 `cea:framing` 消息同步，不重载 iframe。

列表封面按实时缩略图的取景生成：使用同一预览视口，截取播放页报告的内容边界，以 CSS 像素保存原始尺寸。组件封面和实时画面都保留最多 12px 的留白、不放大到原尺寸以上，并应用保存的预览倍率；区块完整适配，整页按宽度显示首屏。参考站的海报不能保证相同构图，应使用实际运行截图作为封面。实时画面排版就绪后直接替换封面，不交叉淡化两幅不同构图，也不让透明区域露出旧封面。

列表实时取景保留缩放计算中的小数位移，与封面图片的居中规则一致；不单独把 iframe 的位置四舍五入到整数像素。组件自身的点击动画继续在原始视口内运行，宿主不改写组件的鼠标坐标或源码。

可见卡片在浏览稳定 600ms 后串行预热，加载和入场预热共用一个后台名额；滚出视口的未完成任务取消，普通驻留实例限制为当前页的 24 个。WebGL 按实际创建的上下文另设 6 个预算，优先释放最久未用的非活动实例，显示原有封面；正在操作的组件不因后台预热被挤掉，单个活动组件自身超过预算时仍保留。封面在首次加载和实例释放后提供画面，预热完成后显示同一 iframe 的清晰暂停画面；已完成预热的带封面组件被释放后，不因滚动返回重复预热，悬停、播放或聚焦时恢复互动。离开后暂停，驻留期间不反复切回封面。封面预热不显示全局加载条。播放地址直接使用摘要中的第一个框架，避免额外的框架重定向请求。

滚动、滚轮输入和列表数据更新期间，不启动新的预览并挂起驻留实例；滚动停止 220ms 后恢复调度，不销毁已完成的实例或清空交互状态。真实鼠标移动后停留 100ms 请求播放，快速划过不启动组件；加载、封面交接和滚动把卡片移到静止光标下面时，不凭进入事件启动播放。iframe 只报告真实鼠标移动，由宿主统一决定播放。连续移动共用同一次等待，不反复延后播放。用户操作中的预览优先于后台预热，其余驻留实例暂时挂起。挂起期间保留入场预热的剩余时间，点击和键盘操作仍可向宿主请求播放；封面点击在完整点击结束后激活，避免按下与松开之间更换命中元素。

暂停同时挂起动画帧、定时器、Web Animation 和媒体；定时器恢复时延续剩余等待，不补跑暂停期间的轮次。动画帧保留浏览器原生时间戳，与 `performance.now()`、文档时间轴和第三方动画库使用同一时钟。后台标签页不启动预热，连续隐藏 30 秒后卸载列表的全部预览；回到前台时，已预热的带封面卡片继续显示封面，无可用封面的可见项和主动请求的卡片才重新加载。搜索、页码和素材数据保留，重新加载的预览内部临时交互状态重新开始。短暂切走保留实例。加载超时只累计前台时间。

播放页报告编译失败、未捕获运行错误、未处理的 Promise 拒绝与 WebGL 上下文丢失。卡片、详情和编辑页共用失败提示与原地重试，就绪后发生错误也能恢复；WebGL 自行恢复时可撤下失败提示。重试期间不把新 iframe 的空白首帧当成已就绪画面。这里不检测所有业务逻辑故障或浏览器进程卡死。

原生弹层按预览可见区域限制位置和滚动高度。使用 `aria-expanded` / `aria-controls` 关联的自定义 `listbox`、`menu` 在超出可见区域时限制列表高度并允许滚动，关闭后恢复原样式；不替换菜单节点或选项事件。

复杂预览示例可以在取景元素上声明 `data-preview-bounds`，或在示例外层声明 `data-preview-bounds="children"`，按其直接子元素的联合边界取景。显式边界不会继续穿透透明容器，也不计入顶层弹窗；未声明的旧素材继续按原有规则测量。使用这一声明时，组件舞台只保留上下 24px 绘制留白，避免超出布局盒的图标和外圈贴着 iframe 顶部被裁掉；横向宽度由示例决定。封面生成必须使用相同的视口、背景和边界，更新后更换封面地址，避免继续命中旧图片缓存。

示例外层自身绘制背景并有 padding 时，应在外层使用 `data-preview-bounds`，把背景和留白一起取景；`children` 适合透明的布局包裹层。只截文字却让实时画面保留外层背景，会导致悬停后背景条变厚或文字比例改变。宽画布封面可以使用更高像素密度改善细文字清晰度，但必须保持与取景边界相同的宽高比；小组件按原尺寸显示时仍需保留 CSS 尺寸，不能直接把双倍像素当作双倍组件尺寸。

组件模式的播放页采用顶部布局锚点，最终居中取景由宿主负责。组件自身变高或变矮时不在 iframe 内反复垂直居中，避免内部移动与外层边界补偿不同步，造成缩小后的文字抖动。该规则不覆盖素材显式声明的布局。

全屏按实际屏幕视口重新排版，去掉设备外壳；常规视图和全屏视图的倍率独立，退出后恢复原来的设备和倍率，不重载 iframe。工具栏默认收起，点击右下角工具入口展开，不响应悬停；工具栏叠放在画面上，不因展开而改变组件视口。

## 配置迁移

配置格式 v2 的 `preferences` 保存框架与内容语言，`ui` 保存网站主题与界面语言；设备尺寸和预设继续保存在 `devices`。预览配色不导出。
导入 v1 时保留框架、内容语言和设备设置，忽略旧预览配色；不覆盖本机已有的网站主题与界面语言。v2 缺少 `ui` 时也保留本机网站偏好。

## 源码与兼容

- 每个框架保存一份原始实现。双主题可以共用一份代码和组件级配色变量，不复制整套文件。
- `theme.mode` 为 `original` 时不注入主题；`light`、`dark` 固定对应配色；`both` 才允许预览切换。`original.default` 不代表已确认的视觉配色。
- 没有声明的旧素材按原样播放，不因检测到某个深色选择器就显示主题开关或注入属性。`resolveTheme` 的检测结果仍供兼容审计使用，不代表已经验证。
- 编辑页的实现设置允许确认主题能力；它不自动生成、删除或修改源码。新实现默认固定配色，不要求补齐双主题。
- AI 目标选择不改变预览、保存的源码或素材声明。即使选择的配色与声明一致，显式选择仍写进提示词；只有沿用原配色不追加目标。
- 分主题思路文案是可选数据，旧文案不必迁移。缺少对应文案时保留原始描述，明确的 AI 配色目标优先。
- 导入导出保留原文件和主题声明，不自动补另一种配色。

## 验证

运行 `npm test`、`npm run typecheck`、`npm run build` 和 `npm run test:browser`。浏览器测试覆盖背景、组件主题、AI 目标之间的隔离，以及原始源码复制。
