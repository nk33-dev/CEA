# 配色与预览

## 状态边界

| 用途 | 入口 | 作用 |
| --- | --- | --- |
| 组件主题 | `AppearanceToggle`、`previewThemeFor` | 只切换明确声明为双主题的实现，初始使用实现声明的默认配色 |
| 舞台背景 | 详情和编辑预览工具栏中的太阳 / 月亮选项，`DeviceBackground` | 只改变组件外的舞台，初始为浅色，不改变源码和 AI 目标 |
| AI 配色目标 | `themeChoices`、`themePrompt` | 沿用原配色、浅色、深色、双主题；只影响生成的提示词 |
| 网站主题 | 顶栏、`PREF_UI_THEME`（`cea:ui:theme`） | CEA 浅色、深色、跟随系统的独立偏好，不控制组件预览 |

详情和编辑页通过 `usePreviewSession` 保存临时预览状态，退出页面即丢弃；AI 目标同样只在当前详情有效。首页始终使用中性浅色舞台和组件原始默认配色。
旧的 `cea:component-theme`、`cea:theme` 本机值不再读取，也不作为网站偏好的回退。
播放页的舞台底色使用 `--cea-background`，不覆盖组件可能使用的 `--stage-bg` 配色变量。

网站主题通过 `html[data-ui-theme]` 和界面 tokens 生效（包括 `--code-editor-bg`、`--code-editor-fg`）；启动时在首屏绘制前恢复偏好。预览舞台使用独立的 `--preview-light` / `--preview-dark`，不要用网站主题重写组件配色或重载 iframe。

## 预览视图

详情和编辑共用 `DeviceWorkspace`。默认「组件」视图按播放页报告的内容边界居中、适配，最多显示到原始大小；不改变组件的 CSS 尺寸。「电脑」「手机」按配置的真实视口排版，再将整个设备缩放进画布。切换视图保留 iframe，尺寸、旋转和缩放只属于当前预览会话。

「组件」和列表缩略图使用居中舞台。「电脑」「手机」使用设备布局，不注入舞台 padding 或强制居中，保留素材自己的间距与排版。布局通过 `framing` 初始参数和 `cea:framing` 消息同步，不重载 iframe。

组件模式的播放页采用顶部布局锚点，最终居中取景由宿主负责。组件自身变高或变矮时不在 iframe 内反复垂直居中，避免内部移动与外层边界补偿不同步，造成缩小后的文字抖动。该规则不覆盖素材显式声明的布局。

全屏按实际屏幕视口重新排版，去掉设备外壳；常规视图和全屏视图的倍率独立，退出后恢复原来的设备和倍率，不重载 iframe。工具栏默认收起，点击右下角工具入口展开，不响应悬停；工具栏叠放在画面上，不因展开而改变组件视口。

## 配置迁移

配置格式 v2 的 `preferences` 保存框架与内容语言，`ui` 保存网站主题与界面语言；设备尺寸和预设继续保存在 `devices`。预览配色不导出。
导入 v1 时保留框架、内容语言和设备设置，忽略旧预览配色；不覆盖本机已有的网站主题与界面语言。v2 缺少 `ui` 时也保留本机网站偏好。

## 源码与兼容

- 每个框架保存一份原始实现。双主题可以共用一份代码和组件级配色变量，不复制整套文件。
- `theme.mode` 为 `original` 时不注入主题；`light`、`dark` 固定对应配色；`both` 才允许预览切换。`original.default` 不代表已确认的视觉配色。
- 没有声明的旧素材按原样播放，不因检测到某个深色选择器就显示主题开关或注入属性。`resolveTheme` 的检测结果仍供兼容审计使用，不代表已经验证。
- 编辑页的实现设置允许确认主题能力；它不自动生成、删除或修改源码。新实现默认固定配色，不要求补齐双主题。
- AI 目标选择不改变预览、保存的源码或素材声明。即使选择的配色与声明一致，显式选择仍写进提示词；只有沿用原配色不追加目标。
- 分主题思路文案是可选数据，旧文案不必迁移。缺少对应文案时保留原始描述，明确的 AI 配色目标优先。
- 导入导出保留原文件和主题声明，不自动补另一种配色。

## 验证

运行 `npm test`、`npm run typecheck`、`npm run build` 和 `npm run test:browser`。浏览器测试覆盖背景、组件主题、AI 目标之间的隔离，以及原始源码复制。
